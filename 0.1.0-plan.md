# 0.1.0 — gf.html foundation: defect fixes, preallocated buffers, canvas drag

Single-file `gf.html`, vanilla classic `<script>`, no modules/no build, `file://` friendly.
Guards `module.exports` so pure helpers also run under `node` for `experiments/`.
Style: single tab, flat helpers, no per-frame allocations, concise why-comments.

## Goal

Make gf lightweight-correct before any content stretch. Fix the four known defects, introduce preallocated typed-array plumbing, and add the canvas drag `dX→period / dY→depth` synced with the GUI. Everything else (presets, textures, views) stays identical so the diff is reviewable.

## Non-goals (explicitly not in 0.1)

New depth presets, palette/tiling textures, image upload, contrast/blur/invert, Thimbleby μ, HSR ray-march, anaglyph/wiggle/relief, WebGL/WebGPU, export, inspector/reticle. Those belong to 0.2–0.4. No brush/shade/paint system (owned by `index.html`).

## Findings from index.html — take vs. leave in 0.1

Take: absolutely-positioned canvases inside `.canvas-wrapper` to break the ResizeObserver loop (already in gf — keep); preallocated buffer discipline (`_ensureBuffers`/`reuse` pattern); grain-after-drift quantization; seeded hash vs `Math.random`.
Leave: `GpuEngine` / WGSL compute, `Heightmap`/`FalloffTable`/`blurShade`, lit renderer, `StereoGUI` bevel carving, shade/ghost passes, fBm terrain, save/load webp — all heavy, not ported.

## Current defects fixed here

1. Fixed-pixel presets: `fillRect(150,120,180,180)`, `arc(460,210,100)`, `110px` font break when the canvas follows its container. Replace with relative sizing (`w*0.x`, `h*0.y`, `min(w,h)*k`) inside `generateDepthMap`. No behavior change at 700×450.
2. Hot-path allocations: per row `new Int32Array(w)` + `new Array(w)` + per pixel `[r,g,b]` + per frame `createImageData`. Preallocate once on resize: `depthF32: Float32Array(w*h)`, `same: Int32Array(w)`, `rowRGBA: Uint32Array(w)`, `outImg: ImageData` + `outU32: Uint32Array` view. `texel(x,y)` returns a packed `Uint32` RGBA. Depth write builds `depthF32` directly; depth view reads it; SIRDS reads it — no `getImageData` red-channel round-trip.
3. Degenerate range: `depthFactor` max 160 > `patternWidth` min 60 → `stereoShift` clamps to 1. Clamp effective shift to ≥8 and clamp `depthFactor` to `period - 8` (or compute `shift = max(8, round(P - z*D))` and expose the clamp in the slider helper). The period slider remains authoritative; depth never inverts the row.
4. Stripe wrap: `(val + … + 255) % 255` off-by-one. Use `& 255` or `% 256`.

## File changes

- `gf.html` only (plus `findings-pitfalls-skills.md` note if a new pitfall is hit).
- Introduce at top: constants `MIN_PERIOD=60, MIN_SHIFT=8`, helpers `clamp(v,lo,hi)`, `periodAt(z,P,D)`, `packRGBA(r,g,b)`.
- Resize path: `resizeCanvas()` allocates/reuses the four buffers when `w*h` grows (exact size when shrinks). `generateDepthMap` writes `depthF32`; `renderSirds` reads it and writes `outU32` then `putImageData(outImg,0,0)` once.
- `generateDepthMap(type)` internals only change scaling; signature and preset names stay `shapes|torus|text3d`.
- `hashNoise`/`simplex3`/`simplexPerm` unchanged.

## Canvas drag: dX → period, dY → depth, synced to GUI

Extends the existing guide-dot drag (which already maps dot separation to period). The new drag is the free canvas area outside the bottom guide strip.

- Hit test: if `pointerdown` is within `GUIDE_HIT` of either dot → existing guide-dot path. Else → tuning drag.
- On `pointerdown` (tuning): `capturedTune=true`, `startX/Y = guidePtr`, `startPeriod = +patternWidthInput.value`, `startDepth = +depthFactorInput.value`, `canvas.setPointerCapture`, add `grabbing` class, `preventDefault`.
- On `pointermove` (tuning): `dx = guidePtr.x - startX`, `dy = guidePtr.y - startY`. Map:
  ```
  period = clampPeriod(startPeriod + round(dx * kPeriod))
  depth  = clampDepth(startDepth  - round(dy * kDepth))   // up is more depth
  clampPeriod = clamp to [patternWidthInput.min, patternWidthInput.max]
  clampDepth  = clamp to [depthFactorInput.min, min(depthFactorInput.max, period - MIN_SHIFT)]
  ```
  Defaults `kPeriod=1.0`, `kDepth=0.6` (≈ 1 px drag ≈ 1 slider unit, vertical a touch softer). Write both sliders' `.value`, call `updateSlidersDisplay()`, `updateExecution()` throttled to `requestAnimationFrame` (one render per frame even if many `pointermove` events), and `drawGuides()` (period changed). While dragging, show `ns-resize`/`ew-resize` hybrid or `grabbing`; update `over-dots` state when not dragging.
- On `pointerup/pointercancel`: clear capture, remove `grabbing`, `saveSettings()` once.
- Sync is bidirectional: any slider `input` already calls `updateSlidersDisplay/updateExecution/saveSettings/drawGuides`; the drag simply writes the same slider values so i18n labels, `val-display`, `localStorage`, and guide-dot separation all follow. No new state variable — sliders stay source of truth.
- Pointer events unify mouse + touch; `touch-action: pan-y` on CSS already allows vertical drag without page scroll stealing (add `touch-action: none` while `capturedTune` if needed).

## i18n and persistence

No new strings in 0.1 (drag needs no label; optional tooltip can be added in 0.2 with 4-lang entries). `saveSettings/loadSettings` already covers `patternWidth/depthFactor`; add clamping on load.

## Validation

- Pixel diff: at default settings (period 100, depth 20, grain 2) CPU output before/after is byte-identical for all three presets at 700×450 (node helper with guarded exports hashes `outU32`).
- Allocations: Chrome allocation timeline flat during animation; `renderSirds` does zero `new` (only buffer views).
- Geometry scale: shapes/torus/text scale correctly at 360×240 and 1280×800; no fixed-pixel seams.
- Degenerate: period 60 + depth 160 no longer produces 1 px shift rows; shift floor is 8 and depth is visibly shallow as expected.
- Drag: pointer drag on canvas changes period/depth sliders, guide-dot distance, and stereogram live; dragging guide dots still changes only period; slider input still updates canvas; `pointercancel` does not leave capture.

## Perf target

Single-thread CPU `renderSirds` ≤16 ms at 700×450, ≤33 ms at 1280×800 on a typical laptop (keeps 30 fps animation after preallocation).
