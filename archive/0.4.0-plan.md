# 0.4.0 — gf.html acceleration: WebGL2 gather with CPU fallback

Depends on 0.1.0–0.3.0 (shipped, see `archive/`). Goal is to make the existing linear SIRDS faster,
not to add content.

## Why this shape

0.1 cached the stereo links and 0.3 made that cache a resolved root map: `linkI32[i]` is the leftmost
column pixel `i` copies its colour from. It is rebuilt only when depth, period, depth scale or HSR
change. The animation frame is already a parallel gather, `out[i] = texel(root(i), y)`. There is no
sequential scan left to port.

Measured CPU cost (node 22, torus, period 100, depth 20, grain 2):

| size | frame (white) | link rebuild, HSR on |
|---|---|---|
| 700×450 | ~3 ms | ~8 ms |
| 1280×800 | ~8 ms | ~25 ms |
| 1920×1080 | ~18 ms | ~40 ms |
| 2560×1440 | ~29 ms | ~90 ms |

The frame is inside budget at 1280×800 and out of it once the canvas follows a large viewport. The
GPU gather is what this version ships. A Web Worker for the link rebuild is **not** in this version:
Chrome blocks workers on `file://`, which is how this page is opened. The rebuild hitch is a later
step, and it has to stay on the page thread (chunked), not in a worker.

## Non-goals

No new depth presets, textures, palettes or views. No WebGPU, no compute shaders, no heightmap
painting. Single HTML file, classic `<script>`, no import maps, no external URLs. Do not re-add the
Thimbleby ray-march — 0.3's two-eye z-buffer is the exact HSR.

## Architecture

### One interface

```
function createSirdsRenderer(canvas)
// -> { kind: 'webgl2' | 'cpu', uploadLinks(linkI32, w, h), render(PAT, w, h),
//      takeSample(), dispose(), lastMs() }
```

`canvas` is the WebGL canvas. The CPU renderer draws the 2D canvas it closes over. `getContext('2d')`
and `getContext('webgl2')` cannot share a canvas, so the wrapper stacks `#glCanvas` between
`#mainCanvas` and `#guideCanvas`.

### CPU path

The 0.1–0.3 gather, unchanged in structure: preallocated buffers, `depthF32`, packed `Uint32` stores,
cached leftmost-root links. It is the pixel reference for `white` and `color`.

### Integer texture, so the two paths can match

`hashNoise` is a uint32 mixer (`HASH_K`), not `Math.sin`. A sin hash is not bit-stable across CPUs
and GPUs, and the parity bar for `white`/`color` is exact. Grain for those two patterns is integer
tenths of a pixel (`tenthsOf` / `grainOrigin` / `floorDiv`): slider steps are 0.1 px, and float32 vs
float64 disagree at cell edges. `HASH_BIAS` keeps the hashed coordinates non-negative so `uint(int)`
is a plain cast (some mobile drivers drop the cast on a negative). `simplex` and `stripe` stay on the
continuous pan; they are allowed a documented channel tolerance.

The same literals live in the fragment shader. `experiments/gl-parity.js` fails if they drift.

### WebGL2 path

- `getContext('webgl2', { antialias: false, alpha: false, depth: false, stencil: false, preserveDrawingBuffer: true })`.
  Null, a missing `createShader`, a compile/link failure, or a texture larger than `MAX_TEXTURE_SIZE`
  → CPU. `file://` blocking WebGL is a normal fallback, not an error. Log compile/link failures;
  stay quiet on a null context.
- `preserveDrawingBuffer: true` is required. `false` clears the drawing buffer after composite, which
  blanks a static stereogram (stable seed, animation off). The frame loop is still `uniform*` +
  `drawArrays` and allocates nothing.
- One triangle from `gl_VertexID`, a bound VAO (some WebGL2 implementations draw nothing without one).
  Fragment shader:
  1. `y = uH - 1 - int(gl_FragCoord.y)` — array row 0 is the top of the image and texture y = 0;
     window y = 0 is the bottom. Do not set `UNPACK_FLIP_Y_WEBGL`.
  2. `root = texelFetch(uLinks, ivec2(x, y), 0).r` from an `R32I` texture.
  3. evaluate `texel(root, y)`, not `texel(x, y)`. The perm table is an `R8UI` texture of
     `simplexPerm`, not a second copy of the bytes.
- `uploadLinks` is `texImage2D` on resize and `texSubImage2D` otherwise. Per frame: uniforms +
  `drawArrays`. Integer textures are `NEAREST` with `TEXTURE_MAX_LEVEL = 0`.
- Hit testing: `#glCanvas` is `pointer-events: none`. When it is showing, `#mainCanvas` stays in the
  tree at `opacity: 0` so the drag still lands on it. `visibility: hidden` would drop the events.

### UI and persistence

- `<select id="renderBackend">` with `auto` (default) / `webgl2` / `cpu`, key `backend` in
  `localStorage`.
- Badge by the title: `⚡ WebGL2` or `CPU (fallback)` (explicit CPU says `CPU`), plus a moving-average
  frame time, DOM text updated at most 4×/s. GPU time comes from `EXT_disjoint_timer_query_webgl2`
  when the browser has it; otherwise the badge shows JS submit time.
- `USE_WEBGL2 = false` at the top of the page script forces the CPU path. The refresh ladder
  (`refreshFrame` / `refreshLinks` / `refreshDepth`) is unchanged; only the leaf render call moves.
- i18n: `lblBackend`, `optAuto`, `optWebGL2`, `optCPU`, `badgeWebGL2`, `badgeCPU` in en/ru/cn/jp.

## Validation

- `experiments/sirds-row.js`, `verify-links.js`, `gf-smoke.js` still pass. Smoke forces no WebGL
  (`getContext('webgl2')` is null) and checks the fallback badge, explicit CPU, and persisted
  `backend`.
- `experiments/gl-parity.js` extracts the shipped shader and checks hash constants, `HASH_BIAS`,
  `GRAD`, the grain formula, the y-flip and the root fetch. With Chrome installed it also draws the
  parity case (`period=120, depth=28, grain=2, preset=shapes`) and requires exact white/color at
  700×450 and 1280×800. simplex/stripe get a logged channel tolerance, not an exact bar.
- `file://` with WebGL blocked still shows an image. Forcing `webgl2` where it is blocked falls back
  and the badge says so.
- Frame loop: no `new`. `texImage2D` only on resize.

## Rollback

`USE_WEBGL2 = false`, or the CPU option in the select. The CPU path stays the source of truth.
