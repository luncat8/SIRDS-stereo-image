# 0.3.0 — gf.html stereo correctness polish (still CPU, still lightweight)

Depends on 0.1.0 and 0.2.0. No build, no modules, `file://` friendly. Keeps the algorithm linear and
the file small; no texture/palette/view buffet.

## Goal

Make the linking correct with a tiny code change. Colliding constraints must not be silently
overwritten, and near-field clutter ("echoes") must be suppressible without a heavy ray-march.

## Non-goals

Thimbleby optical projection (`μ` slider, `E = 2P` reparametrization); tile textures and palettes;
percolation/noise ramps; anaglyph/wiggle/relief/tilt/AO; WebGL. `sirdsAlgo` stays `linear`.
Any painting/shade/brush system is owned by `index.html`.

## Findings from index.html / ag.html — take vs. leave in 0.3

Take: one `periodAt(z, P, D)` helper shared by guide dots, drag clamp, status readout and renderer;
ag.html's zero-allocation union-find with leftmost roots and its per-scanline `leftZ`/`rightZ`
z-buffers.
Leave: full Thimbleby `s = round((1−μz)E/(2−μz))` with μ UI, iterative relaxation / error readback,
lit renderer. ag.html's own fill pass reads `same[x]` rather than a resolved root — correct only by
accident of left-to-right ordering; gf resolves roots explicitly so the pass is a pure gather.

## Changes

### One separation helper

```js
function periodAt(z, period, depthScale) {
	const s = Math.round(period - z * depthScale);
	return s < MIN_SHIFT ? MIN_SHIFT : s;   // MIN_SHIFT = 8
}
```

Every inline `basePeriod - z*depthScale` is gone. Exported through the `gf-core` markers for node.

### Linking: leftmost-root union-find

`same[right] = left` drops the earlier constraint whenever two links collide. Replace with union-find
whose root is always the leftmost index, so `links[i] <= i` is an invariant.

Per scanline, writing straight into the cached `linkI32` row (no extra buffer, no allocation):

```
init      links[x] = x
link      for x: s = periodAt(z); left = x - (s>>1); right = left + s
          skip if out of bounds or hidden
          ra = find(left); rb = find(right)      // while-loop with path halving
          if ra != rb: links[max(ra,rb)] = min(ra,rb)
flatten   for x in 1..w-1: r = links[x]; if r != x: links[x] = links[r]
fill      out[x] = (links[x] === x) ? texel(x, y) : out[links[x]]
```

The flatten pass is a **single** left-to-right hop, not a loop: `links[x] <= x` guarantees every
index below `x` is already resolved. That makes the fill a pure gather — and the same root map is
what a GPU fragment shader would sample in 0.4.

### Visibility: exact two-eye z-buffer, not a ray-march

All surface points that map to the same left-eye pixel lie on that eye's ray, so only the nearest
may claim it — that is a z-buffer, and it is `O(w)` with two reused `Float32Array(w)`:

```
pass 1   leftZ[left]  = max z over all x with left  = x - (s>>1)
         rightZ[right]= max z over all x with right = left + s
pass 2   skip the link if z < leftZ[left] - HSR_EPS  ||  z < rightZ[right] - HSR_EPS
```

`HSR_EPS = 0.01` keeps a smooth slope from shredding itself on rounding.

This supersedes the Thimbleby march rather than approximating it. For the record, the march's linear
equivalent is `zt = z + 2t/D` (from `s(z') = s(z) − 2t` with `s = P − zD`), hiding the link when
`depth[x±t] >= zt` for `t = 1…` while `zt < 1` — up to `D/2` steps per pixel, versus one pass here.

Exposed as a single checkbox `Hide hidden surfaces`, default **on**. No μ slider.

### Why this is affordable

The links depend only on depth, period and depth scale (0.1's link cache), so both the union-find
and the z-buffer run on a control change, never inside the animation loop. Measured at 1280×800:
16.5 ms with HSR off, 27.8 ms with HSR on — both off the hot path, while the animation frame stays
at ~11 ms.

### Integration with the 0.1 drag

`periodAt` backs the drag's depth clamp (`depth ≤ P − MIN_SHIFT`) and the depth readout
`20 px  (80…100 px)`. `drawGuides` still spaces the dots by `P`. No drag behaviour change.

## Validation

`node experiments/verify-links.js` audits the **rendered image**, recomputing the visibility rule
independently, with 24-bit colour noise at grain 1 so an accidental repeat is ~1/16M:

- *constraints met* — every link the depth map demands must be two byte-equal pixels.
- *ghost shifts* — pixels that also repeat at some other shift, i.e. a second wrong depth for the eye.

| preset | union-find, hsr off | union-find, hsr on | naive `same[right]=left` |
|---|---|---|---|
| shapes | 100% · 8.5% ghosts | 100% · 0.0% | 98.79% · 4.8% |
| torus | 100% · 11.9% | 100% · 2.2% | 98.18% · 9.1% |
| heart | 100% · 8.8% | 100% · 4.1% | 98.51% · 6.2% |
| ripples | 100% · 30.6% | 100% · 13.7% | 95.69% · 20.7% |
| pyramid | 100% · 3.0% | 100% · 0.0% | 98.93% · 2.7% |

Union-find satisfies every constraint; the old overwrite drops 1–4% of them. HSR removes ghosts
outright on the hard-edged presets and halves them on the smooth ones.

`experiments/sirds-row.js` additionally asserts `links[x] <= x`, that links point straight at a root,
that HSR frees occluded pixels (they fall back to fresh noise) and that HSR is a **no-op on a flat
surface** — a plane has nothing to occlude, so the toggle must not disturb it.

`experiments/render-png.js` writes `pyramid-sirds.png` vs `pyramid-sirds-hsr-off.png` for eyeballing.

## Perf budget

Union-find adds `O(α(w))` per link; the z-buffer adds one `O(w)` pass. Both are cached. Frame budget
unchanged at ≤33 ms for 1280×800.

## i18n / persistence

One new row `lblHsr` in en/ru/cn/jp; `hsr` bool in `saveSettings`/`loadSettings`, default on.
