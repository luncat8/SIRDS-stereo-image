# 0.2.0 — gf.html lightweight depth content

Depends on 0.1.0. Single file, no modules/no build, `file://` friendly. Keeps gf lightweight — no
painting system, no tile/palette explosion, no views beyond stereogram + depth.

## Goal

More depth variety without bloat. Make every preset container-relative, add the cheapest pure-math
presets and a custom-text field, and keep post-processing to invert + contrast.

## Non-goals

Image upload, palette editor, tile textures (blobs/confetti/tartan/tie-dye/wood), zoom/density,
domain-warped noise, gradient maps, anaglyph/wiggle/relief/tilt, Thimbleby μ, blur, save/load maps,
WebGL/GPU. Deferred to 0.3–0.4 or left in `index.html` / `ag.html`.

**Blur is closed, not deferred.** Contrast + invert cover the need; a separable box blur would add a
second full-size scratch buffer and a radius slider for no visible gain on these presets.

## Findings from index.html — take vs. leave in 0.2

Take: depth as `Float32Array 0..1` (adopted in 0.1) as the single source; geometry relative to `w,h`.
Leave: `fillNoise` fBm terrain (allocates 4 arrays per call, needs lacunarity/gain/octaves UI), lit
renderer, `Heightmap`/`FalloffTable`/`stamp`, `blurShade` — not ported.

## Presets — one flat table, all scale-invariant

`DEPTH_PRESETS = { shapes, torus, heart, ripples, pyramid, text3d }`, each a
`(depthF32, w, h) => void` filler. The five pure-math ones live inside the `gf-core` markers so node
can render and diff them; only `text3d` needs the DOM.

| preset | geometry | depth profile |
|---|---|---|
| `shapes` | rect `(w·0.17, h·0.26, w·0.26, h·0.42)`, circle `(w·0.67, h·0.48, r = min(w,h)·0.155)` | 0.55 / 0.95 flat |
| `torus` | `maxR = min(w,h)·0.31`, `minR = maxR·0.36` | `max(0, 1 − |dist−mid| / thick) · 0.90` |
| `heart` | `hx = (x−cx)/s`, `hy = (cy−y)/s`, `s = min(w,h)·0.30`, `cy = h·0.52` | `f = (hx²+hy²−1)³ − hx²·hy³`; inside (`f < 0`): `0.25 + 0.70·min(1, cbrt(−f))` |
| `ripples` | `rr = dist · 2/min(w,h)` (normalized, **not** raw pixels) | `(cos(rr·3.5·2π) + 1) · 0.45 · max(0, 1 − rr·0.75)` |
| `pyramid` | `q = max(|x−cx|/(w·0.30), |y−cy|/(h·0.38))`, 5 steps | `q < 1 ? ceil((1−q)·5)/5 · 0.95 : 0` |
| `text3d` | offscreen canvas, bold `h·0.28` px, auto-shrunk to `w·0.86` | drop layer 150/255, face 255/255, sampled from the red channel |

Background is a flat `0` (true far plane) for every preset.

`cbrt(−f)` is what turns the heart from a flat silhouette into a bulge: `−f` is ~1 at the centre and
0 on the outline, and the cube root spreads that into an even dome.

Ripple radius **must** be normalized. An absolute `dist·0.06` would contradict the scale-invariance
this plan exists for: the ring count would change with the canvas size.

`text3d` **must** measure and shrink the font (`measureText` → scale to `w·0.86`), or a 12-character
custom string runs off the canvas. It rasterizes on its own `textCanvas` with
`willReadFrequently: true`, so the visible canvas keeps a hardware backend and is never read back.

## Custom text

`<input type="text" id="depthText" maxlength="12" value="3D LAB">` in its own `.control-group`,
shown only while `depthPreset === 'text3d'` (`refreshDepth` toggles the row). `input` →
`refreshDepth` → `saveSettings`. Persisted. No font picker, no second canvas.

## Post-process

Applied in place to `depthF32` right after the preset fill, inside `generateDepthMap`, so it runs on
a depth change and never per animation frame:

```
sign = invert ? -1 : 1;  base = invert ? 1 : 0
z = (base + sign*z - 0.5) * contrast + 0.5   // clamped 0..1
```

Branch-free so the whole map is one linear pass. `invert` is a checkbox (default off), `contrast` a
range `0.2 … 3` step `0.1` (default `1.0`).

## UI and persistence

New controls reuse the `.control-group` pattern; checkbox rows use `.control-group.row` instead of
inline styles. New i18n rows in all four languages: `optHeart`, `optRipples`, `optPyramid`,
`lblCustomText`, `lblInvert`, `lblContrast`. `optText3d` drops the hard-coded `"3D LAB"` from its
label since the string is editable now. `saveSettings`/`loadSettings` gain `depthText`,
`depthContrast`, `depthInvert`; `loadSettings` rejects an unknown preset name via `DEPTH_PRESETS`.

The depth readout doubles as a correctness display: `20 px  (80…100 px)` — the near and far
separations straight out of `periodAt`, so a degenerate setting is visible before it is rendered.

## Validation

- `render-png.js` writes `<preset>-depth.png` / `<preset>-sirds.png` at any size — every preset was
  inspected at 700×450 and stays centred and proportionate (no fixed-pixel artifacts).
- `gf-smoke.js` asserts each preset fills a real depth range (`max − min > 40/255`) and that the
  custom-text row, contrast and invert survive a save/load round trip.
- `perf.js` — depth generation is off the animation path; the per-frame cost is unchanged from 0.1.

## Perf budget

No animation-frame regression vs 0.1. Depth generation runs only on a control change or resize.
