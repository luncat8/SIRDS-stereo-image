# 0.2.0 worklog — lightweight depth content

## Plan review before implementing

Three spec bugs found and corrected in `archive/0.2.0-plan.md`:

- **heart** — the plan said `z = 0.2 + 0.8*edgeDist` but never defined `edgeDist`. Implemented as
  `0.25 + 0.70·min(1, cbrt(−f))` where `f` is the implicit heart value: `−f` is ~1 at the centre and
  0 on the outline, and the cube root turns it into an even dome instead of a flat silhouette.
- **ripples** — the plan's `cos(dist*0.06)` is in absolute pixels, which contradicts the
  scale-invariance the same plan is about (ring count would change with canvas size). Normalized to
  `rr = dist · 2/min(w,h)`.
- **text3d** — no font fitting was specified, so a 12-character custom string would run off the
  canvas. Added `measureText` → shrink to `w·0.86`.

Also decided: **blur is closed, not deferred**. Contrast + invert cover the need and a box blur
would cost a second full-size scratch buffer plus a slider.

## Steps

1. Five pure-math fillers (`fillShapes`, `fillTorus`, `fillHeart`, `fillRipples`, `fillPyramid`)
   moved *inside* the `gf-core` markers, so `experiments/render-png.js` renders the real presets.
   Only `fillText3d` stays in the DOM layer.
2. `DEPTH_PRESETS` flat table replaces the `if (type === …)` chain; `generateDepthMap` is 4 lines.
3. `fillText3d` rasterizes on its own `textCanvas` with `willReadFrequently: true` — the visible
   canvas keeps a hardware backend and is never read back.
4. Custom text input, shown only for `text3d`; `refreshDepth` toggles the row.
5. `postProcessDepth` — branch-free invert + contrast in one pass, inside `generateDepthMap`, so it
   never touches the animation loop.
6. Six new i18n rows in en/ru/cn/jp; `optText3d` lost its hard-coded `"3D LAB"` now that the string
   is editable. Checkbox rows moved from inline styles to `.control-group.row`.
7. Depth readout now shows the separation range from `periodAt`: `20 px  (80…100 px)`.

## Validation

```
node experiments/render-png.js /tmp/gfpng 700 450
node experiments/gf-smoke.js
```

- Depth PNGs inspected at 700×450: heart is a centred dome with a clean cusp and cleft, ripples show
  ~4 concentric rings with a radial falloff, pyramid shows 5 clean terraces, shapes/torus centred.
- `gf-smoke.js` asserts every preset fills a real depth range (`shapes 0..242`, `torus 0..229`,
  `heart 0..242`, `ripples 0..229`, `pyramid 0..242`) and that `depthText`, `depthContrast` and
  `depthInvert` survive a save/load round trip.
- Depth generation stays off the animation path — the per-frame table in `logs/perf-0.3.0.md` is
  unchanged from 0.1.

Minor follow-up during review: `shapes` was top-heavy after the first relative rewrite, so the rect
moved to `h·0.26` and the circle grew to `min(w,h)·0.155` for a balanced composition.
