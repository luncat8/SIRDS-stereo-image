# 0.3.0 worklog — stereo correctness polish

## Plan review before implementing

The plan's HSR section was the weak part. It proposed "at most one neighbour check or a bounded
2-step walk" and described tracking `leftZ`/`rightZ` in prose that did not say what the test was,
while deferring "a true Thimbleby march" to 0.4.

Derivation done during review: with linear separation `s(z) = P − zD`, two points share an eye ray
when `s(z') = s(z) − 2t`, i.e. `zt = z + 2t/D`. That is exactly the march — but it also means **all
points mapping to the same eye pixel are on that eye's ray**, so keeping the max `z` per eye pixel
is a z-buffer: exact, `O(w)`, one pass, no stepping. The march is at most `D/2` steps per pixel for
the same answer. So 0.3 ships the *exact* test and the march is dropped from 0.4 rather than
deferred to it. Recorded in `findings-pitfalls-skills.md`.

Second improvement: the flatten pass. Because the union keeps the leftmost index as root, the
invariant `links[x] <= x` holds, so resolving roots is a **single** left-to-right hop
(`links[x] = links[links[x]]`), not a loop. ag.html skips the flatten entirely and gathers from
`same[x]`, which works only because the fill happens to run left-to-right; gf resolves explicitly so
the root map is also valid for a parallel (GPU) gather.

## Steps

1. `linkRow(depth, links, rowOffset, w, period, depthScale, useHsr, leftZ, rightZ)` in the core —
   init, optional z-buffer pass, union-find with path halving, single-hop flatten. It writes
   straight into the cached `linkI32` row, so there is no separate `same` buffer.
2. `HSR_EPS = 0.01` so smooth slopes are not shredded by rounding.
3. `hsrToggle` checkbox, default on; `lblHsr` in 4 languages; `hsr` persisted.
4. `buildLinks()` loops the scanlines and clears `linksDirty`; `refreshLinks()` is the only thing
   that sets it, so the animation loop never pays for either pass.

## Validation

```
node experiments/verify-links.js   # audits the rendered image, not the linker's bookkeeping
node experiments/sirds-row.js
node experiments/render-png.js
```

`verify-links.js` recomputes the visibility rule independently and uses 24-bit colour noise at
grain 1, so an accidental repeat is ~1/16M. It runs the old naive linker side by side:

| preset | union-find hsr off | union-find hsr on | naive `same[right]=left` |
|---|---|---|---|
| shapes | 100% · 8.5% ghosts | 100% · 0.0% | 98.79% · 4.8% |
| torus | 100% · 11.9% | 100% · 2.2% | 98.18% · 9.1% |
| heart | 100% · 8.8% | 100% · 4.1% | 98.51% · 6.2% |
| ripples | 100% · 30.6% | 100% · 13.7% | 95.69% · 20.7% |
| pyramid | 100% · 3.0% | 100% · 0.0% | 98.93% · 2.7% |

- Union-find satisfies **every** constraint; the old overwrite silently dropped 1–4% of them.
- HSR removes ghost shifts entirely on the hard-edged presets and roughly halves them elsewhere.
- `sirds-row.js` also confirms HSR frees occluded pixels (32 px on the test step row, which then get
  fresh noise) and is a **no-op on a flat surface** — a plane has nothing to occlude.

Cost, 1280×800: link rebuild 16.5 ms hsr off / 27.8 ms hsr on, both only on a control change; the
animation frame stays ~11 ms.

## A note that was nearly a wrong turn

An earlier validation attempt tried to recover depth by finding, per pixel, the *smallest* repeating
shift. It reported 22–87% agreement and looked like a failure. It is not a valid metric: a linked
group spans many positions, so a shorter valid repeat inside the same group is expected, especially
on smooth presets. The metric was replaced with constraint satisfaction plus an explicit ghost rate.
Kept here so the same dead end is not re-explored.
