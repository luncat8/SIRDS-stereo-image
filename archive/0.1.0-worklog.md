# 0.1.0 worklog — foundation

Implemented together with 0.2.0 and 0.3.0 in one pass over `gf.html` (790 → ~900 lines).

## Plan review before implementing

The plan as written had two problems, both corrected in `archive/0.1.0-plan.md`:

- *"CPU output before/after is byte-identical for all three presets at 700×450"* is unachievable and
  contradicts the same plan's defect 1 — replacing `fillRect(150,120,180,180)` with `w·0.x / h·0.y`
  moves the geometry by design. Replaced with scale/constraint/perf validation.
- Defects 3 and 4 were listed but four more were found while reading the file: the depth
  `getImageData` round-trip forcing `willReadFrequently` on the visible canvas, the torus drawing
  `fillRect(x,y,1,1)` per pixel, `loadSettings` restoring `currentMode` without syncing the toggle
  buttons, and the animation loop re-rendering identical frames when the seed is stable and drift
  is zero. Dead `optBw` / `'bw'` legacy was removed under the AGENTS "no leftovers" rule.

One design addition beyond the plan: **caching the link map**. Links depend only on depth, period
and depth scale, never on the animation frame, so they moved out of the per-frame loop into
`linkI32` rebuilt by `refreshLinks()`. This is what later made 0.3's hidden-surface pass free.

## Steps

1. Split the script into a DOM-free core (`// >>> gf-core start` … `// <<< gf-core end`, guarded
   `module.exports`) and the DOM layer, so node tests run the shipped code instead of a copy.
2. `MIN_SHIFT`, `clamp`, `periodAt`, `packRGBA`; every inline separation formula now calls `periodAt`.
3. `ensureBuffers(w,h)` allocates `depthF32`, `linkI32`, `hsrLeftZ/RightZ`, `outImg` + `outU32`.
   Frame loop is one packed store per pixel and one `putImageData`.
4. `texel(x,y)` returns packed RGBA and reads the preallocated `PAT` scratch object — no closures,
   no per-pixel arrays. Stripe wrap `% 255` → `& 255`.
5. Presets rewritten relative to `w`/`h`; torus writes the buffer directly.
6. Refresh ladder `refreshFrame` / `refreshLinks` / `refreshDepth`; controls wired from one flat
   `CONTROL_ACTIONS` table instead of scattered listeners.
7. Canvas drag: `DRAG_DOTS` (period only, near the guide dots) vs `DRAG_TUNE` (`dX`→period,
   `dY`→depth), both throttled to one `requestAnimationFrame` apply. `touch-action: none`.
8. `setMode()` owns `currentMode` + both toggle buttons; `loadSettings` re-clamps the period/depth
   pair through `setPeriodAndDepth`.

## Validation

```
node experiments/sirds-row.js     # 20/20 checks
node experiments/gf-smoke.js      # 26/26 checks, stub DOM boots the real <script>
node experiments/perf.js          # logs/perf-0.3.0.md
```

- `periodAt(1, 60, 160) === 8` — the degenerate period-60/depth-160 row is fixed; the smoke test
  confirms the slider itself is clamped to 52 when the period drops to 60.
- Drag: `100 → 160` period on `dx = +60`, `20 → 56` depth on `dy = −60`; guide-dot drag leaves depth
  untouched; `pointerup` ends the capture.
- Static settings push 0 extra frames over 5 rAF ticks, drifting noise pushes 5.
- Frame cost 5.4 ms at 700×450 and 10.9 ms at 1280×800 (white noise) — budget was 16 / 33 ms.

No browser exists in the sandbox, so `gf-smoke.js` (stub DOM) plus `render-png.js` (PNG output)
stand in for manual inspection; both are reusable regression harnesses.
