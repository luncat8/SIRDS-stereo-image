# 0.1.0 — gf.html foundation: defect fixes, preallocated buffers, canvas drag

Single-file `gf.html`, vanilla classic `<script>`, no modules/no build, `file://` friendly.
The DOM-free math sits between `// >>> gf-core start` / `// <<< gf-core end` markers and is guarded
with `module.exports`, so `experiments/` can load the shipped code under node.
Style: single tab, flat helpers, no per-frame allocations, concise why-comments.

## Goal

Make gf lightweight-correct before any content stretch. Fix the known defects, introduce
preallocated typed-array plumbing, and add the canvas drag `dX→period / dY→depth` synced with the
GUI. Presets/textures/views stay the same set so the diff is reviewable.

## Non-goals (explicitly not in 0.1)

New depth presets, palette/tiling textures, image upload, contrast/blur/invert, Thimbleby μ, HSR,
anaglyph/wiggle/relief, WebGL/WebGPU, export, inspector/reticle. Those belong to 0.2–0.4.
No brush/shade/paint system (owned by `index.html`).

## Findings from index.html — take vs. leave in 0.1

Take: absolutely-positioned canvases inside `.canvas-wrapper` to break the ResizeObserver loop
(already in gf — keep); preallocated buffer discipline (`_ensureBuffers`/reuse pattern);
grain-after-drift quantization; seeded hash vs `Math.random`.
Leave: `GpuEngine` / WGSL compute, `Heightmap`/`FalloffTable`/`blurShade`, lit renderer,
`StereoGUI` bevel carving, shade/ghost passes, fBm terrain, save/load webp — all heavy, not ported.

## Defects fixed here

1. **Fixed-pixel presets.** `fillRect(150,120,180,180)`, `arc(460,210,100)`, `110px` font break when
   the canvas follows its container. Size everything from `w`, `h`, `min(w,h)`.
2. **Hot-path allocations.** Per row `new Int32Array(w)` + `new Array(w)`, per pixel `[r,g,b]`,
   per frame `createImageData`. Preallocate once per resize; the frame loop does zero `new`.
3. **Depth round-trip through the canvas.** Depth was drawn with 2D calls and read back with
   `getImageData`, so the visible canvas needed `willReadFrequently: true` (software backend) and
   depth was quantized to 8 bit. Depth becomes `Float32Array 0..1`, written directly.
4. **Torus drew per-pixel `fillRect(x, y, 1, 1)`** — hundreds of thousands of canvas calls per
   regeneration. It becomes a plain buffer write.
5. **Degenerate range.** `depthFactor` max 160 > `patternWidth` min 60, so `stereoShift` clamped to
   1 px and the row smeared. `periodAt` floors the separation at `MIN_SHIFT=8` and the depth slider
   is clamped to `period − MIN_SHIFT` whenever either slider or the drag moves.
6. **Stripe wrap.** `(val + … + 255) % 255` can never produce 255 and skips a value. Use `& 255`.
7. **Mode not restored.** `loadSettings` restored `currentMode` but never synced the two toggle
   buttons, so a reload in depth mode showed "Stereogram" as active. One `setMode(mode)` owns both.
8. **Idle burn.** A stable seed with `vx = vy = 0` renders an identical frame forever; the loop
   re-rendered it every rAF. Skip when nothing can change.
9. **Dead legacy.** `optBw` i18n row and the `patternType === 'bw'` mapping had no UI. Removed
   (AGENTS: no legacy support, no leftovers).
10. **`.controls` used `margin-top:auto`** on the generate button without being a flex column.

## Buffers (allocated in `ensureBuffers(w,h)` on resize only)

| buffer | type | role |
|---|---|---|
| `depthF32` | `Float32Array(w*h)` | depth 0..1, single source of truth |
| `linkI32` | `Int32Array(w*h)` | per pixel, the leftmost index to copy the colour from |
| `hsrLeftZ` / `hsrRightZ` | `Float32Array(w)` | per-scanline eye z-buffers (used from 0.3) |
| `outImg` / `outU32` | `ImageData` + `Uint32Array` view | one packed store per pixel, one `putImageData` per frame |

`packRGBA(r,g,b)` packs little-endian RGBA; `texel(x,y)` returns a packed `Uint32`.

## Link cache — the architectural decision of 0.1

The stereo links depend only on `depthF32`, `period` and `depthScale` — **not** on the animation
frame. Build them into `linkI32` when those change and leave the animation loop as a pure gather:

```
render: for each pixel  r = linkI32[i];  outU32[i] = (r === i) ? texel(x, y) : outU32[rowStart + r]
```

Because the root is always the leftmost index of its group, the source pixel is already written.
This keeps the per-frame cost proportional to one texel lookup per group, makes the 0.3 hidden
surface pass free at animation time, and hands 0.4 a GPU-friendly gather.

Three refresh levels, cheapest first, so a period tweak never re-rasterizes text:

- `refreshFrame()` — texture/grain/drift/view changed: redraw only.
- `refreshLinks()` — period/depth/HSR changed: clamp, rebuild links, redraw, redraw guides.
- `refreshDepth()` — preset/text/contrast/invert/resize changed: regenerate depth, then the above.

## Canvas drag: dX → period, dY → depth, synced to the GUI

Extends the existing guide-dot drag (dot separation ↔ period). The new drag is the rest of the canvas.

- `pointerdown`: within `GUIDE_HIT` of either dot → `DRAG_DOTS` (period only); otherwise `DRAG_TUNE`.
  Record `dragStart{x, y, period, depth}`, `setPointerCapture`, add `.grabbing`, `preventDefault`.
- `pointermove` while dragging: store the pointer, schedule **one** `requestAnimationFrame(applyDrag)`
  so many pointer events collapse into one render per frame.
  ```
  period = clampPeriod(startPeriod + dx * 1.0)
  depth  = clampDepth (startDepth  - dy * 0.6, period)   // up is more depth
  clampDepth -> [min, min(max, period - MIN_SHIFT)]
  ```
- `pointerup`/`pointercancel`: release capture, cancel a pending rAF, `saveSettings()` once.
- No new state: the drag writes the same slider `.value`s the GUI writes, so `val-display`,
  `localStorage` and the guide-dot separation all follow from one source of truth.
- CSS `touch-action` becomes `none` (was `pan-y`): vertical drag is now a control axis, so the page
  must not steal it. The page still scrolls from the controls panel and the rest of the document.

## i18n and persistence

One new string, `hintDrag`, in en/ru/cn/jp. `saveSettings`/`loadSettings` already cover
`patternWidth`/`depthFactor`; `loadSettings` re-clamps the pair through `setPeriodAndDepth` and
restores the view mode through `setMode`.

## Validation

Byte-identical output vs. the old build is **not** a goal and not achievable: relative sizing
intentionally changes the preset geometry, and the union-find/HSR work in 0.3 changes linking.
What is checked instead (`node experiments/*.js`, logs in `experiments/logs/`):

- `sirds-row.js` — `periodAt(0,P,D) === P` for P ∈ {60,100,400,640}; `periodAt(1,60,160) === 8`
  (degenerate range fixed); `links[x] <= x`; links point straight at a root; every surviving link
  is byte-equal in the output; stripe red channel reaches 255; a pan of one grain shifts the stable
  pattern exactly.
- `gf-smoke.js` — stub DOM boots the real `<script>`: canvas follows the wrapper, a frame is pushed,
  every preset and texture renders, depth is clamped below the period, drag `dX`/`dY` moves both
  sliders, the guide dots stay period-only, `pointerup` releases the capture, settings persist,
  static settings skip redraws and drifting noise does not.
- `perf.js` — frame budget, see below.

## Perf target and measurement

Per-frame gather+texel, median of 20 (node 22, `preset=torus`, `period=100`, `depth=20`, `grain=2`):

| size | white | color | simplex3d | stripe | link rebuild (off hot path) |
|---|---|---|---|---|---|
| 700×450 | 5.4 ms | 5.4 ms | 6.0 ms | 3.6 ms | 7.3 ms |
| 1280×800 | 10.9 ms | 12.3 ms | 12.1 ms | 10.0 ms | 16.5 ms |

Budget ≤16 ms at 700×450 and ≤33 ms at 1280×800 — met with headroom. Link rebuilds happen only on a
control change, so a slider drag costs one extra rebuild per frame, not per frame forever.
