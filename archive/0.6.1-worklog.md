# 0.6.1 worklog — HSR audited, then turned off by default

## Question

Is the "hide hidden surfaces" pass in `gf.html` broken, or just ugly at a large grain? It looked
like the latter: the freed pixels read as smears once the noise grain went up. If it is only a
taste problem, the fix is the default, not the code.

## Audit

`experiments/hsr-audit.js` (new) checks the pass against a reference built the other way round.
The shipped `linkRow` scatters forward — every surface point writes its depth into the two eye
pixels it lands on, then keeps the pair only if it is still the closest writer. The reference
gathers instead: for each eye pixel it collects the full list of claimants and takes the nearest.
A row is correct when the rendered image satisfies **100%** of the constraints that reference
demands, on 24-bit colour noise at grain 1 where an accidental repeat is ~1/16M.

## Result: no bugs

| preset | required | satisfied | dropped |
|---|---|---|---|
| shapes | 84613 | 84613 | 0 |
| torus | 84036 | 84036 | 0 |
| heart | 85418 | 85418 | 0 |
| ripples | 81842 | 81842 | 0 |
| pyramid | 85068 | 85068 | 0 |

Also verified: the eye buffers cannot leak from one row into the next, HSR is a no-op on a flat
surface, a depth step does relink, and `HSR_EPS` keeps a sub-tolerance step linked while
suppressing a step past it.

## Why it is off by default

A suppressed point leaves its two pixels unsourced, so they sample the pattern at their own `x`
instead of a stretched one, and they come in runs:

| preset | freed px | longest run | mean run |
|---|---|---|---|
| shapes | 2.3% | 21 px | 10.4 px |
| torus | 2.8% | 2 px | 1.0 px |
| heart | 1.5% | 7 px | 2.3 px |
| ripples | 4.6% | 3 px | 1.1 px |
| pyramid | 1.8% | 3 px | 2.8 px |

A 21 px run at grain 16 is a 336 px blob of texture that was never stretched, and the eye reads
that as a smear rather than as a hidden surface. `experiments/render-png.js` now writes the
`*-g16-hsr-on.png` / `*-g16-hsr-off.png` pair so the claim can be checked by eye.

## Changes

- `#hsrToggle` no longer ships `checked`.
- `hsr` is out of `saveSettings`/`loadSettings`. Every load starts from the HTML default, which
  also drops the stale `hsr: true` that the old default-on wrote into every existing save — a
  stored value cannot tell "the user ticked it" from "the user never saw a choice".
- `experiments/gf-smoke.js` boots from a seeded old save: HSR must come up off while the other
  settings in that save still restore, and `hsr` must not appear in what is written back.
- `experiments/render-png.js` gained the grain-16 HSR pair.

## Next step

If a future HSR is to be on by default it has to stop leaving free pixels: fill a suppressed pair
from the nearest surviving link of the same row instead of dropping it, and re-check the ghost
rate in `verify-links.js` so the fix does not trade the smear for a second wrong depth.
