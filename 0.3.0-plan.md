# 0.3.0 — gf.html stereo correctness polish (still CPU, still lightweight)

Depends on 0.1.0 and 0.2.0. No new build, no modules, `file://` friendly. Keeps the algorithm linear and the file small; no texture/palette/view buffet.

## Goal

Make the SIRDS linking correct with a tiny code change. Colliding constraints must not be silently overwritten, and near-field clutter ("echoes") should be suppressible without a heavy ray-march.

## Non-goals

Thimbleby optical projection (`μ` slider, `E = 2P` reparam) — correct but heavier UI and re-parametrization; tile textures and palettes; percolation/noise ramps; anaglyph/wiggle/relief/tilt/AO; WebGL. Those stay out (or go to 0.4). Any painting/shade/brush system is owned by `index.html`.

## Findings from index.html — take vs. leave in 0.3

Take: the separation helper `periodAt(z)` used by guide dots and renderer (single function, no duplicated formula); the principle that colliding links need a rule, not just `same[right]=left`.
Leave: full Thimbleby `s = round((1-μz)E/(2-μz))` with μ UI, iterative relaxation/error readback, lit renderer — heavy for a lightweight polish.

## Changes

### Depth as float, one helper

- Depth is already `depthF32` (0.1). Add one pure helper used by every view and the dot layout:
  ```
  function periodAt(z, P, D){ return Math.max(8, Math.round(P - z*D)); }
  ```
  Replace inline `basePeriod - z*depthScale` math with it. Guard with `module.exports` for node experiments.

### Linking fix: leftmost-root union-find (small, correct)

Current gf (and `0.1` fixes) does `same[right]=left` overwrite. When two links collide, the later one silently drops the earlier constraint. Replace with union-find where each root stays the leftmost index (`same[i] <= i`) and fill copies from the root.

Per scanline `y` (reuse preallocated `same: Int32Array(w)` from 0.1, no alloc):

```
for x in 0..w-1  same[x]=x
for x in 0..w-1
  z = depthF32[y*w+x]
  s = periodAt(z, P, D)
  left  = (x - (s>>1)) | 0
  right = left + s
  if left>=0 && right<w && visible(x,z,left,right)
    ra = find(left); rb = find(right)   // path-compress while loop
    if ra!=rb  same[max(ra,rb)] = min(ra,rb)
for x in 0..w-1
  r = same[x]; outRow[x] = (r===x) ? texel(x,y) : outRow[r]
find(v){ while(same[v]!==v){ same[v]=same[same[v]]; v=same[v]; } return v; }
```

`find` is inline loops, no recursion/closure per frame (avoid allocation). `texel` stays the existing `hashNoise`/`simplex3`/`stripe` sampler with grain-after-drift and `stableNoise` seed logic, returning packed `Uint32`.

### Visibility (cheap HSR toggle, default ON)

Provide a single checkbox `Hide hidden surfaces` that suppresses links that should be occluded. For linear mode the cheapest sufficient test is local: keep per-row arrays `leftZ/rightZ` (or just compare neighbor depth) — but the minimal correct addition is to forbid a link when its left or right endpoint is already claimed by a strictly nearer surface:

- During the link pass, if `useHsr` and `depthF32[y*w+left]` or `depthF32[y*w+right]` already holds a nearer `z` (tracked in two `Float32Array(w)` reused per scanline), skip the union. This prevents the common "echo" without a full Thimbleby ray-march.
- If a true Thimbleby march is wanted later, implement it in 0.4 as: for link `(left,right)` at `z`, step `t=1…` while `zt = z + 2(2-μz)t/(μE) < 1` and hide if `depth[y*w±t] >= zt`. Keep 0.3 cheap: at most one neighbor check or a bounded 2-step walk.

No new UI beyond the one HSR toggle; no μ slider.

### Integration with 0.1 drag

`periodAt` is used by drag clamping (`depth ≤ P-8`) and by `drawGuides` dot separation (still `P`). No drag behavior change; the row fix only affects `renderSirds`.

## Validation

- `experiments/sirds-row.js` (node, no DOM): synthesize a row with `z = [0,0,0.8,0.8,0]` and assert every linked pair `(x, x+s)` has byte-equal `outRow` and that the row hash changes only where expected when toggling HSR off→on (echo pixels appear with HSR off).
- At `z=0` across widths 400/700/1280, `periodAt(0,P,D) === P`.
- Visual: step pyramid/heart silhouettes have crisp edges, no ghost fringes when HSR on; toggling HSR off shows the fringe (confirms the toggle does something).
- Allocation check still flat (reuse `same`/`leftZ`/`rightZ`).

## Perf budget

Union-find adds O(α(w)) per link, negligible. HSR neighbor check adds O(w) with no alloc. Frame budget stays ≤33 ms at 1280×800.

## i18n / persistence

Add one i18n row `lblHsr` in en/ru/cn/jp; persist `hsr` bool in `saveSettings/loadSettings`. States: `sirdsAlgo` stays `linear` (no new algo string).
