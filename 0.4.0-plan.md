# 0.4.0 — gf.html acceleration: WebGL2 path with CPU fallback (next version)

Depends on 0.1.0–0.3.0. Goal is to make the existing linear SIRDS fast by adding a GPU path, not to add content.

## Goal

Ship a `WebGL2` fast path that reuses the exact same depth/noise math, with an automatic CPU fallback so the file stays `file://` usable everywhere. Default is WebGL2; if context creation, shader compilation, or `file://` quirks fail, the app silently uses the proven CPU loop from 0.1–0.3. User can lock the choice.

## Non-goals

No new depth presets, textures, palettes, or views (relief/anaglyph/wiggle). No WebGPU (broader compat with WebGL2), no compute-shader bundle, no heightmap painting/shade/ghost. File stays single-HTML, classic `<script>`.

## Findings from index.html — take vs. leave in 0.4

Take: the shape of a GPU engine — probe at startup, preallocate GPU resources once per resize (`_ensureBuffers`), upload depth once per preset change, upload small uniform block per frame, keep one `requestAnimationFrame` loop. Adapt the `_ensureBuffers`/`writeBuffer`/`dispatch` discipline to WebGL2 (`createTexture`/`texImage2D`/`uniform*`).
Leave: WGSL `WGPU_*` compute pipelines, `relax` iterations, error atomic readback, brush compute, `StereoGUI` bevel heightmap, heightmap lit renderer — heavy and SIRDS-irrelevant here.

## Architecture

### Single interface

```
function createSirdsRenderer(canvas){
  // probes WebGL2, returns
  // { kind: 'webgl2'|'cpu', render(params), dispose(), getMs() }
}
params = { w,h, period:P, depthScale:D, depthF32, patternType, grain,
           moveX, moveY, stable, animFrame, hsrOn, viewMode }
render() writes to `canvas` via `putImageData` (CPU) or `drawArrays`+`readback` avoidance (WebGL2 blits directly to canvas).
```

Pure helpers (`periodAt`, `hashNoise`, `simplex3`, `packRGBA`, row linker) stay guarded:

```js
if(typeof module!=='undefined' && module.exports) module.exports = { periodAt, hashNoise, simplex3 };
```

so `experiments/` can load them under node and compare CPU vs GPU hashes.

### CPU path (fallback, already shipping)

The optimized CPU `renderSirds` from 0.1–0.3: preallocated `same/rowRGBA/outImg`, `depthF32` source, packed `Uint32` texel sampler with grain-after-drift, union-find leftmost-root. Used verbatim when `kind==='cpu'` and as the reference for pixel-correctness tests.

### WebGL2 path (default when available)

- Probe: `canvas.getContext('webgl2', {antialias:false, preserveDrawingBuffer:false})`. If null → CPU.
- Shaders: one vertex shader (full-screen triangle) + one fragment shader that implements the same math as the CPU row loop: compute `z = texDepth`, `s = periodAt(z)`, resolve links by sampling neighboring texels (the fragment approach iterates over `x` in parallel; constrain to linear `s=P-zD` so no divergence). Textures: `depthTex` (`R8`/`R32F` depending on `EXT_color_buffer_float` availability; fallback packs depth into RGBA8), `outTex` framebuffer.
- Alternatives: if fragment linking proves costly, fall back to CPU linking on the CPU but do the `texel` generation + `putImageData` via WebGL upload (still a win). Keep the first version simple and measure; no need for transform-feedback/compute.
- Resource lifecycle: `_ensureGLBuffers(w,h)` creates/resizes textures + FBO once per canvas size. Per preset change: `gl.texSubImage2D(depthTex, depthF32)`. Per animation frame: `gl.uniform1f(period)`, `gl.uniform1f(depthScale)`, `gl.uniform1f(moveX/Y)`, `gl.uniform1i(animFrame)`, `gl.drawArrays`.
- Compile guard: `gl.getShaderParameter(..., gl.COMPILE_STATUS)` + `gl.getProgramParameter(..., gl.LINK_STATUS)`; on fail, log to console (when available) and fall back to CPU without showing a stack to the user — just flip the badge to "CPU (fallback)".
- `file://` guard: some browsers block WebGL2 on `file://`; treat `getContext` null as normal fallback, not an error.

### UI and persistence

- Controls: `<select id="renderBackend"><option value="auto">Auto (WebGL2 → CPU)</option><option value="webgl2">WebGL2</option><option value="cpu">CPU</option></select>` or a toggle. Default `auto` (means: try WebGL2, else CPU). Persist `renderBackend` in `localStorage`. Small badge near the title: `⚡ WebGL2` / `CPU (fallback)` (+ last render ms when available). No new per-frame strings — update badge/status at most 4×/s from a moving average.
- All existing controls keep behavior: sliders, guide-dot drag, canvas `dX/dY` tuning (0.1) still write the same slider values; they just trigger `renderer.render` via either path.
- i18n: add `lblBackend`, `optAuto`, `optWebGL2`, `optCPU`, `badgeWebGL2`, `badgeCPU` rows in all 4 languages.

### Copy-paste safe

No ES modules, no import maps, no external URLs. `vendor/` only if a tiny `gl-matrix` is needed — otherwise inline. File stays openable by double-click.

## Validation

- Compatibility: open `gf.html` via `file://` in Chrome/Firefox/Safari — with `backend=auto` the app always shows an image (GPU or CPU). Forcing `WebGL2` on a `file://` that blocks it falls back and shows "CPU (fallback)".
- Correctness: for `period=120, depth=28, grain=2, pattern=white, preset=shapes` at 700×450 and 1280×800, `hash(hashNoise)` of `outU32` between CPU and WebGL2 paths differs by ≤1 LSB for ≥99% pixels (tolerance for `R8` packing vs `f32`); with `R32F` available difference is 0.
- Perf: 1280×800 white/color animated (stable seed off) — CPU ≥30 fps, WebGL2 ≥55 fps on a mid laptop; `renderMs` logged in `experiments/logs/`.
- Allocation: `gl.texImage2D` only on resize; per-frame loop does `uniform*` + `drawArrays` with no JS `new`.

## Rollback plan

If WebGL2 path regresses or doubles file size, keep it behind `backend=cpu` default or gate with a `USE_WEBGL2=false` constant at the top. The CPU path remains the source of truth; GPU is additive.
