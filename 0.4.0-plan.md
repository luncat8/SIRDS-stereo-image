# 0.4.0 — gf.html acceleration: WebGL2 gather with CPU fallback (next version)

Depends on 0.1.0–0.3.0 (shipped, see `archive/`). Goal is to make the existing linear SIRDS faster,
not to add content.

## What changed since this plan was first written

0.1 introduced the **link cache** and 0.3 made it a resolved root map: `linkI32[i]` holds the
leftmost index pixel `i` copies its colour from, and it is rebuilt only when depth, period, depth
scale or HSR change — never per animation frame. Two consequences kill most of the original design:

- The old plan worried that "fragment linking proves costly" and sketched a fallback where linking
  stays on the CPU. That is now simply the architecture: linking is *already* off the hot path.
- The remaining per-frame work is `out[i] = texel(root(i), y)`, which is **embarrassingly parallel**.
  There is no sequential scan left to port. A fragment shader samples the root map and evaluates the
  texture function — no dependencies between pixels.

Measured CPU baseline (node 22, median of 20, `logs/perf-0.3.0.md`):

| size | per-frame gather+texel | link rebuild (control change only) |
|---|---|---|
| 700×450 | 3.6 – 6.0 ms | 7.3 ms off / 8.4 ms on |
| 1280×800 | 10.0 – 12.3 ms | 16.5 ms off / 27.8 ms on |

So the honest framing for 0.4: the animation frame is already inside budget at 1280×800. The GPU is
worth it for larger canvases and for headroom; the *worst* current stall is the HSR link rebuild
while dragging a slider on a big canvas.

## Decide first, then build

Measure before writing shaders. Two candidates, one afternoon each:

- **A — WebGL2 fill.** Upload `linkI32` on rebuild, evaluate `texel` in a fragment shader per frame.
  Attacks the 10–12 ms frame. Ceiling: ~1 ms.
- **B — Worker link rebuild.** Move `buildLinks` to a Web Worker with a transferable `Int32Array`.
  Attacks the 16–28 ms stall during slider drags. Keeps everything else identical, no shaders, no
  feature detection, ~40 lines. `file://` workers are blocked in Chrome, so it needs the same
  graceful fallback as A.

Ship A as the plan of record below; keep B in scope as a cheaper alternative if A's pixel parity
proves fiddly.

## Non-goals

No new depth presets, textures, palettes or views. No WebGPU (WebGL2 has broader reach), no compute
shaders, no heightmap painting/shade/ghost. Single HTML file, classic `<script>`, no import maps, no
external URLs. **The Thimbleby hidden-surface ray-march is not deferred here — 0.3's two-eye
z-buffer is the exact same result in one `O(w)` pass. Do not re-add it.**

## Architecture

### One interface

```
function createSirdsRenderer(canvas)
// -> { kind: 'webgl2' | 'cpu', uploadLinks(linkI32, w, h), render(PAT, w, h), dispose(), lastMs() }
```

`periodAt`, `hashNoise`, `simplex3`, `packRGBA`, `texel`, `linkRow` and the depth presets stay in the
`// >>> gf-core start` block with the `module.exports` guard, so `experiments/` keeps comparing CPU
and GPU output through the same node harness.

### CPU path (fallback, already shipping)

`renderSirds` from 0.1–0.3 verbatim: preallocated buffers, `depthF32` source, packed `Uint32` texel
sampler with grain-after-drift, cached leftmost-root link map. It is the reference for pixel parity.

### WebGL2 path

- Probe `canvas.getContext('webgl2', { antialias: false, preserveDrawingBuffer: false })`. Null →
  CPU. Some browsers block WebGL2 on `file://`; treat that as a normal fallback, not an error.
- One full-screen triangle; the fragment shader:
  1. reads `root = texelFetch(linkTex, ivec2(gl_FragCoord.xy), 0).r` — the root **column** for this
     row, stored as `R32I` (or `RG8` packed if `EXT_texture_norm16`-style integer targets are
     unavailable);
  2. evaluates the same texel function at `(root, y)` — the four pattern branches port directly;
     `hashNoise`'s `sin`-based hash is bit-fragile across GPUs, so validate parity per pattern and
     accept a documented tolerance for `simplex3d`/`stripe` if needed.
- Resources: `ensureGLBuffers(w,h)` creates the link texture and the program once per canvas size.
  `uploadLinks` runs `texSubImage2D` on a link rebuild only. Per frame: `uniform*` + `drawArrays`.
- Compile guard: check `COMPILE_STATUS` / `LINK_STATUS`; on failure log to console and fall back to
  CPU silently, flipping the badge to `CPU (fallback)`.

### One canvas, two contexts — the trap

`getContext('2d')` and `getContext('webgl2')` are mutually exclusive on the same canvas. The 2D path
is still needed for the depth view. Either render the depth view through WebGL2 too, or keep a
second stacked canvas (the wrapper already stacks `#mainCanvas` and `#guideCanvas` absolutely) and
toggle visibility. Pick the second — it is smaller and keeps the CPU path untouched.

### UI and persistence

- `<select id="renderBackend">` with `auto` (default) / `webgl2` / `cpu`, persisted in
  `localStorage`. Badge near the title: `⚡ WebGL2` / `CPU (fallback)` plus a moving-average
  frame time, updated at most 4×/s.
- All existing controls keep behaviour. The drag, the guide dots and the refresh ladder
  (`refreshFrame` / `refreshLinks` / `refreshDepth`) are the contract; only the leaf render call
  changes.
- i18n rows `lblBackend`, `optAuto`, `optWebGL2`, `optCPU`, `badgeWebGL2`, `badgeCPU` in all 4 langs.

## Validation

- Extend `experiments/verify-links.js`: the GPU output must satisfy 100% of the stereo constraints,
  same as CPU. This is the real correctness bar, and it already runs headless.
- Pixel parity: for `period=120, depth=28, grain=2, pattern=white, preset=shapes` at 700×450 and
  1280×800, CPU vs WebGL2 must match exactly for `white`/`color` (integer arithmetic). Document the
  measured tolerance for `simplex3d`/`stripe`.
- `experiments/gf-smoke.js` must still pass with `backend=cpu` forced (the stub DOM has no WebGL).
- Compatibility: open via `file://` in Chrome/Firefox/Safari — `auto` always shows an image.
  Forcing `webgl2` where it is blocked falls back and says so.
- Perf: 1280×800 animated, CPU ≥30 fps (already true), WebGL2 ≥55 fps. Log to `experiments/logs/`.
- Allocation: `texImage2D` on resize only; the frame loop does `uniform*` + `drawArrays`, no JS `new`.

## Rollback

`USE_WEBGL2 = false` at the top of the file, or ship with `backend=cpu` default. The CPU path
remains the source of truth; the GPU is additive.
